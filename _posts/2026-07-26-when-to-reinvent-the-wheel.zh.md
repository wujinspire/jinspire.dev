简而言之：

- 智能体（Agents）正在主导编程领域。
- 重复造轮子——复刻（fork）并提取你需要的部分——正成为更好的实践。
- 为学习而优化已成为直觉编程（vibe coding）成功的关键。
- 学习基础知识，理解系统设计，避免过度设计，并及时重构。
- 避免错失恐惧症（FOMO），专注于重要的事情。
- 模型进步很快，但人类进步得更快。

## 编程模型的最新进展


注：我是在 2026 年 6 月 21 日开始写这篇草稿的，但直到今天才有时间发布。

距离我上次写关于直觉编程的文章已经有一段时间了。几乎就在一年前，我还在吹嘘自己用 Cursor 半年写了一百万行代码。我没有分享更多相关内容，部分原因是我工作太忙，部分原因是用智能体编程已经成为行业标准。然而，我并没有停止直觉编程。随着模型变得越来越好，我写的代码也越来越多了。

编程模型的最新进展是什么？

首先，什么是最好的编程模型？Fable？GPT-5.6 Sol？Opus 5？这是一个高度主观的问题，我将从历史的角度分享我的看法。

- 曾经有一段时间，Opus 4.5 遥遥领先于市场上的任何其他模型。GPT-5.0 到 GPT-5.2 基本上都是垃圾。在那个时候，人们开始相信 Anthropic 将主导 AI 的未来。
- 这种趋势持续了一段时间，直到 Anthropic 算力极度短缺，开始对其模型进行激进的量化，这使得人们开始寻找替代方案。那时，它还没有与 xAI/SpaceX 签署租用算力的协议。
- Gemini 3 在调试一些复杂案例时仍然有用，但遗憾的是，谷歌已经太久没有更新其模型了。Gemini 3.5 Pro 陷入了困境。更糟糕的是，人们正在离开——Noam Shazeer、John Jumper，以及几位曾与我共事过的副总裁。
- 回到第一季度，我严重依赖 Opus 4.5，但绝对讨厌模型量化导致的性能下降。GPT-5.3 Codex 开始引起我的注意。它的表现出人意料地好，尽管人们对产品线和令人困惑的模型名称（GPT-5.3 和 GPT-5.3 Codex 是不同的模型）抱怨不断。
- 然后 OpenAI 做出了改变。他们意识到需要将编程作为他们的主要战场。他们放弃了 Sora，将所有算力集中在 Codex 上。他们还将模型发布统一在 GPT-5.4 之下，这确实是一个伟大的模型，让他们重新回到了竞争中。
- 接着是 GPT-5.5，这是一个现象级的模型，我用它写了大部分代码。它的 token 效率极高。它非常擅长处理 GitHub Actions。它非常擅长推理。它非常擅长终端 CLI。它的幻觉少了很多。我想说，它绝对是当时最好的编程模型。
- 但它并非无所不能：它写的前端代码非常糟糕。这在过去似乎不是什么大问题，但没有哪个直觉程序员能抵挡住构建前端进行可视化的诱惑。
- Mythos/Fable 5 似乎再次改变了游戏规则。我想说，它的延迟发布确实给了 OpenAI 一些追赶的时间。它绝对不是 AGI。差得远呢。当人们把期望值设得太高时，围绕它的神秘感很容易让人失望。它确实是一个好模型。它的能力绝对远超 Opus 4.8。我不认为它在大多数领域都优于 GPT-5.5，但在许多领域确实如此。
- 但它太慢了。而且它还被封禁了 :)
- （7 月 26 日更新：它又可以用了，而且 Opus 5 也发布了。）
- 接着是 GPT-5.6 Sol，它显著提升了前端编程能力。
- Kimi K3，一个 2.8 万亿参数的模型，是编程界的另一颗原子弹。
- 然后是 Opus 5，它的速度和质量让 Opus 再次具备了竞争力。
- 所以我个人对编程模型的排名是：GPT-5.6 Sol >= Opus 5 > Fable 5。


## 运行框架

既然我们已经讨论了模型，现在是时候讨论智能体运行框架的当前趋势了。
- Cursor 作为领先的智能体运行框架平台，曾陷入 Claude 的束缚，拼命转向 Kimi 2.5，并陷入了转型的泥潭。在 IPO 热潮中，SpaceX 最终收购了它，当时 600 亿美元相对于 SpaceX 的估值来说只是个小数目。这对双方来说绝对是一笔划算的交易。
- Claude Code 绝对占据了大部分市场。它确实是现象级的。我个人仍然喜欢使用 Cursor，但我必须承认 Claude Code 的伟大。
- 接着是 Claude Code 和 Codex 之间的主要战役。两者都瞄准了同一个市场。两者都提供 CLI、VS Code 扩展、云端智能体和桌面应用程序。
- 桌面应用程序绝对是一项伟大的发明。但我不得不说，两者都仍在改进中。Claude Cowork 的幻觉让它完全无法使用。但 Claude Cowork 在功能上绝对具有先发优势，而 Codex 应用程序在易用性上则更为领先。
- 我真的很喜欢使用 Codex 应用程序来完成多项任务：编程、规划、幻灯片、Slack 机器人等。显然，Codex 应用程序赢得了这场战斗。

是时候谈谈真正的主题了——工作流。
- 人们一直在谈论目标（goals）、循环（loops），现在又在谈论图（graphs）。我认为这些都是华而不实的术语，忽略了本质。如果你知道自己想要什么，前沿模型已经具备了交付这些结果的能力。
- 以我为例：在看到 MVP（最小可行性产品）之前，我通常不知道自己到底想要什么。我从不相信设计文档，尽管我在谷歌沉浸于设计文档文化中度过了四年。它们在这个新世界里行不通。先构建一些东西，尝试它，然后迭代，这样效率要高得多。我不相信在构建出东西之前，你能预测所有的错误或瓶颈。

对我来说，运行框架本身并不是真正的焦点。它很快就会走进死胡同——真正重要的是掌握以任何格式表达你意图的技能。随着将意图转化为代码的成本变得越来越低，软件工程最古老的法则之一开始瓦解：不要重复造轮子。


## 重复造轮子


一方面，如果第三方库完全满足你的需求，你不应该重复造轮子。另一方面，拥有代码能让你获得更多控制权，并让你迭代得更快，而不是焦急地等待可能引入新错误的下一个版本。


智能体时代让我更频繁地倾向于第二个选项。

有了这些强大的工具，重复造轮子变得容易多了——复刻（fork）一个现有的项目，提取你需要的部分，并将其引入你自己的代码库中。这曾经是一种糟糕的做法，但它正变得越来越普遍，在某些情况下甚至成为了更好的选择。

正如那句名言所说：“我在广告上花的一半钱都浪费了；问题是我不知道是哪一半。”这同样适用于决定何时重复造轮子：我们知道它在某些情况下有效，但我们不知道是哪些情况。指导这一决定的**原则**是什么？


## 真实与虚假的论点

我一直是单一代码库（monorepo）的信徒。我发现跨多个代码库的开发比在单一代码库中开发要慢得多。我还发现大多数第三方软件写得很糟糕。有些人将其归咎于 AI 和直觉编程。我认为他们完全错了。我见过人类写出更糟糕的代码。而 AI 生成的垃圾代码应该归咎于接受它的工程师。

另一个糟糕的论点是，如果你重复造轮子，你将无法再轻松地拉取上游更新。这是一个虚假的说法。每当你需要上游更新时，你都可以要求 AI 准确提取你需要的更改。

对于任何严肃的项目，当你意识到需要更改第三方代码库中的某些内容时，就是复刻它并将有用部分提取到你自己代码库的好时机。这是我简单的经验法则，其背后的真实论点很简单：为速度和可靠性而优化。

回到编程：真正的瓶颈是什么？


## 真正的瓶颈

你在两个方面是真正的瓶颈：基础知识和学习速度。
- “你才是真正的瓶颈”这句话不是我发明的。这是硅谷的常识。当你整天管理多个 AI 会话并进行上下文切换时，你会感到筋疲力尽。Karpathy 曾在 *No Priors* 播客中说他经历了 AI 精神病和 token 焦虑。我深有同感。这种工作流创造了一种虚假的成就感和生产力，同时又让你焦虑自己没有进行足够的多任务处理来真正释放 AI 的全部潜力。
- 幸运的是，这种感觉已经有了一个专有名词——错失恐惧症（FOMO）。解决方案很简单：专注于重要的事情。一个经常被归功于沃伦·巴菲特的流行练习说：“列出你最重要的 25 个目标，选出最重要的 5 个，然后把剩下的 20 个扔进垃圾桶。它们成为了你的‘不惜一切代价避免’清单，意味着绝对不能分心。”同样的原则也适用于这里。
- 让我们来分解这两个瓶颈。
- 首先，知识永远是速度的基础。如果你有扎实的编程知识，你就能轻易发现智能体的幻觉和过度设计。是的，过度设计一直是智能体最大的问题。当多个会话积累了技术债务时，系统很难扩展。通常只需要一个好主意（有时只需一个提示词）就能让代码变得更有结构、更有条理——这正是 AI 并不总是擅长的地方。将所有东西塞进一个拉取请求（PR）通常也是一种反模式。基础编程知识是根本。如果你懂系统设计，引导你的智能体构建一个可扩展的系统就会容易得多。这可能是拥有和缺乏丰富软件工程经验的人之间最大的区别。
- 没有人无所不知。智能体能帮助你更容易地进入一个领域。最大化你在该领域的学习速度是个好主意，而不是祈祷你的智能体解决一切问题，自己只负责验证结果。通过提问和学习基本概念，你的学习、成长和迭代速度会快得多。知识实际上是无限的，但你能深刻理解并应用的设计模式是有限的。在你理解这些模式之前，完全信任你对目标、循环或图的设计并不是一个好主意。
- 对我来说，学习速度的一个限制因素是阅读速度。现在大多数日常编程任务都涉及阅读理解。我发现我阅读英文的效率不高，所以我一直用中文与我的智能体交流。语言混合不再仅仅是模型的问题；现在它也是我的问题了 :) 我需要努力改善这一点。
- 总的来说，我发现理解基础知识——概念、设计模式和数据流——让我受益匪浅。


那么，硅谷当前真正重要的趋势是什么？
- 人们相信一切都可以被编码。我从中看到了很多真理。
- 人类才是瓶颈。据此进行优化，这在很大程度上意味着为学习而优化。

模型已经进步了很多，但使用它们的人进步得更快。
